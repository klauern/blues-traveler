## Overview

Google Gemini offers multiple automation and hook capabilities across three main product areas:
1. **Gemini CLI** - Command-line AI agent with comprehensive hook system

## 1. Gemini CLI Hooks System

### Introduction
- **Announcement:** Hooks were introduced in Gemini CLI v0.26.0+ (enabled by default)
- **Definition:** Scripts or programs that execute at specific, predefined points in the CLI's lifecycle
- **Purpose:** Function as "middleware" for your AI assistant, allowing customization without touching source code
- **Execution Model:** Synchronous - CLI waits for all matching hooks to complete before continuing

### Core Capabilities

With hooks, you can:
- **Add Context:** Inject relevant information (git commits, Jira tickets, local documentation) before model processing
- **Validate Actions:** Review and block potentially dangerous operations before execution
- **Enforce Policies:** Implement organization-wide security and compliance requirements
- **Log and Optimize:** Track tool usage and dynamically adjust tool selection
- **Notifications:** Get updates when CLI is idle, awaiting input, or requires confirmation

### Hook Event Types

1. **SessionStart**
   - Fires on application startup, resuming session, or after `/clear` command
   - Use case: Loading initial context

2. **BeforeAgent**
   - Fires before sending a request to the LLM
   - Operates on stable, SDK-agnostic request format
   - Use case: Prompt augmentation, context injection

3. **BeforeToolSelection**
   - Fires before LLM decides which tools to call
   - Use case: Filter available toolset, force specific tool modes

4. **BeforeTool**
   - Executes before tool execution
   - Use case: Argument validation, security checks, parameter rewriting
   - **Security Example:** Prevent writing sensitive data (API keys, passwords) to codebase

5. **AfterTool**
   - Executes after tool execution
   - Use case: Process results, log outputs, trigger follow-up actions

6. **BeforeModel**
   - Runs before model processes input
   - Use case: Sophisticated prompt augmentation, request modification

7. **AfterModel**
   - Runs after model outputs
   - Fires immediately after LLM response chunk received
   - Use case: Real-time redaction, PII filtering

8. **BeforeResponse / AfterChunk**
   - Fires for every chunk generated by the model
   - Note: AfterChunk does not support decision, continue, or systemMessage

9. **AfterAgent**
   - Fires once per turn after model finishes final response
   - Use case: Post-processing, session cleanup

10. **SessionEnd**
    - Fires when CLI exits or session is cleared
    - Use case: Cleanup, final telemetry

11. **Notification**
    - Fires when agent needs user attention
    - Use case: Updates when CLI is idle or awaiting input

12. **BeforeCompress**
    - Fired asynchronously before context compression
    - Note: Cannot block or modify compression process (flow-control fields ignored)

13. **AfterAlert**
    - Observability only, cannot block alerts or grant permissions
    - Note: Flow-control fields are ignored

### Matchers

Hooks use matchers to filter which events trigger them:
- **Tool events** (BeforeTool, AfterTool): Use Regular Expressions (e.g., `write_.*`)
- **Lifecycle events** (e.g., `startup`): Use Exact Strings
- **Wildcards:** `*` or `""` (empty string) matches all occurrences

### Configuration

Hooks are configured in `settings.json` with the following precedence (highest to lowest):
1. **Project settings:** `.gemini/settings.json` in current directory
2. **User settings:** `~/.gemini/settings.json`
3. **Extension-defined hooks:** Bundled with installed extensions

### Hook Types

1. **Command Hooks**
   - Run shell commands
   - Communicate via exit codes and stdin/stdout

2. **Plugin Hooks**
   - Discover and load npm packages labeled with `geminicli-plugin`
   - Validate declared API version
   - Inject services (Logger, Config, HttpClient) into hook methods

### Communication Protocol

- **Input:** JSON via stdin
- **Output:** JSON via stdout
- **Logs:** stderr for logs and feedback

### Management Commands

The `/hooks` CLI command includes subcommands:
- `panel` - View and manage hooks
- `enable` - Enable specific hooks
- `disable` - Disable specific hooks
- `migrate` - Migrate hook configurations

## 2. Gemini Code Assist

### Overview
- **Purpose:** AI-powered coding assistant for IDEs (VS Code, JetBrains, Android Studio)
- **Key Features:** Code completion, generation, transformation, chat, and agent mode
- **Editions:** Standard (enterprise-grade security) and Enterprise (customizable with private repos)

### Supported IDEs and Languages
- **IDEs:** VS Code, IntelliJ IDEs, Android Studio
- **Languages:** Many popular languages with contextualized responses

### Code Transformation Commands
- `/fix` - Fix issues or errors in code
- `/generate` - Generate code
- `/doc` - Add documentation to code
- `/simplify` - Simplify code

### Custom Commands

Users can create custom commands for repetitive tasks:
- **Access:** Gemini Code Assist Quick Pick menu (Ctrl+I / Cmd+I in VS Code)
- **Location:** Settings > Tools > Gemini > Prompt Library (JetBrains)
- **Examples:**
  - `/add-comments` - Add comments following specific patterns
  - `/add-exception-handling` - Generate exception handling code
  - Scaffold new components
  - Generate test cases

### Configuration Features (VS Code Extension)

1. **Inline Suggestions Control**
   - Path: Extensions > Gemini Code Assist > Inline Suggestions: Enable Auto list
   - Options: On/Off (Control+Enter / Control+Return for manual triggering)

2. **Privacy and Telemetry Settings**
   - Control sending usage statistics and crash reports to Google

3. **Recitation/Citation Controls**
   - Set `Recitation: Max Cited Length` to 0 to block code suggestions matching cited sources

4. **Custom Commands**
   - Add via VS Code → Extensions → Gemini Code Assist → Settings

5. **Update Channel**
   - Determines extension version (Default = latest tested version)

6. **Preview Features**
   - Enable for Gemini 3 in agent mode

### Context Files Automation

- **Context Sources:** IDE files, local system folders, tool responses, prompt details
- **Manual Context:** Use `@FILENAME` syntax to include specific files
- **Automatic Exclusion:** Files in `.aiexclude` or `.gitignore` are excluded by default
- **Gemini CLI Context:** `GEMINI.md` files provide persistent context across interactions

### Agent Mode

**Availability:** VS Code and IntelliJ IDEs (Preview feature)

**Core Capabilities:**
- Ask code-related questions
- Generate code from design documents, issues, TODO comments
- Handle complex, multi-file tasks
- Analyze entire codebase
- Propose plans and await approval
- Control agent behavior through commenting, editing, approving

**Built-in Tools:**
- File operations
- Code analysis
- Project searching
- Version control capabilities
- All Gemini CLI built-in tools

**Advanced Features:**
- **MCP Server Integration:** Configure MCP servers to extend agent abilities
- **Multi-File Editing:** Proposes plans and awaits approval before making changes
- **Context Management:** Uses dedicated context files for better responses

**Agentic Workflows:**
Developers can delegate multi-step workflows where Gemini reasons through steps using external tools (Git, test runners, Cloud Run, BigQuery, deployment services)

### Rules Feature

Guide Gemini Code Assist on project-specific conventions to ensure generated code aligns with team's established libraries and best practices.

## 3. Gemini Code Assist Enterprise - Code Customization

### Overview
- **Purpose:** Get code suggestions based on organization's private repositories
- **Alignment:** Coding style aligned to organizational standards

### How It Works
1. **Indexing:** Private code indexed every 24 hours
2. **Matching:** Searches private index for similar code
3. **Prompting:** Includes relevant matches in code prompts
4. **Suggestions:** Sends to Gemini Code Assist recommendations service

### Use Cases
- Natural language chat
- Generating or transforming code in IDE
- Automatic autocomplete suggestions

### Security and Privacy
- **Single-tenant storage:** Isolated storage for your organization
- **Access controls:** IAM permissions
- **No training:** Google does not train on your code
- **Private results:** Your code not shared with other users
- **Queried only:** Code queried as part of your request only

### Repository Support
- **Hosted:** github.com, gitlab.com, bitbucket.org
- **On-premises:** GitLab Enterprise, GitHub Enterprise, Bitbucket Data Center

### Configuration Options
- **IAM permissions:** Control data access
- **`.aiexclude` file:** Prevent specific files/repositories from being indexed

## 4. Gemini API - Function Calling

### Overview
- **Purpose:** Get structured data outputs from generative models
- **Use Case:** Call other APIs and return relevant response data to model
- **Alternative Name:** "Tool use" (allows model to use external tools/APIs/functions)

### Callbacks with Live API

The Live API (WebSocket-based) uses callbacks:
- `onopen` - Connection opened
- `onmessage` - Message received
- `onerror` - Error occurred
- `onclose` - Connection closed

**Important Note:** Unlike `generateContent` API, Live API doesn't support automatic tool response handling - you must handle tool responses manually in client code.

### Automatic Function Calling

**Python SDK Feature Only:**
- `ChatSession` automatically executes functions when `automatic_function_calling` is enabled
- SDK automatically calls function and sends another request to Gemini with function result

### Function Calling Modes
1. **Manual Control:** Developer explicitly handles function calls
2. **Automatic Execution:** SDK handles function calling automatically

### Use Cases for Automation
- Scheduling appointments
- Creating invoices
- Sending reminders
- Checking order status
- Processing returns
- Updating customer information

## 5. Gemini API - Streaming

### Server-Sent Events (SSE)

**Endpoint:** `streamGenerateContent`
- **Purpose:** Stream chunks of response as they are generated
- **Benefit:** Faster, more interactive experience for chatbots

**Response Structure:**
- `responseId` - Ties full response together
- `candidates` array - Contains content objects with model's response

### Live API (WebSocket)

**Overview:** Stateful, bi-directional streaming API

**Connection Endpoint:**
```
wss://generativelanguage.googleapis.com/ws/google.ai.generativelanguage.v1beta.GenerativeService.BidiGenerateContent
```

**Capabilities:**
- Send text, audio, or video to Gemini server
- Receive audio, text, or function call requests from Gemini server
- Initial message sets session configuration (model, generation parameters, system instructions, tools)

**Function Calling Features:**
- Request client to execute `functionCalls` and return responses with matching IDs
- Cancel tool calls that should not have been executed (with side-effect undo attempts)

**Real-Time Processing:**
- Manages bi-directional stream
- Enterprise flow: User App → Backend Server → Gemini Live API

## 6. Gemini API - Batch Processing

### Overview
- **Purpose:** Process large volumes of requests asynchronously
- **Cost:** 50% less than standard rate
- **Turnaround:** Target 24 hours (often much quicker)
- **File Size:** Up to 2GB JSONL files

### Workflow
1. Package all requests into single file
2. Submit file
3. Retrieve results once job completes

### Technical Capabilities
- **High-throughput:** Engineered for large-scale workloads
- **Context Caching:** Optimizations for greater efficiency
- **Multimodal:** Supports images, audio, video via File API
- **Tool Use:** Supports built-in Google Search functionality

### Use Cases
- Content generation
- Data annotation and classification
- Offline analysis

### Cost Efficiency
- 50% discount applies directly to per-token pricing
- Applies to any supported model in batch mode

## 7. Gemini CLI - Skills

### Overview
- **Purpose:** Repeatable workflow framework for complex multi-step tasks
- **Behavior:** Similar to agent tools but with on-demand prompts and supporting files

### Structure
- **Folder-based:** Each skill is a folder
- **Contents:**
  - Prompt
  - Supporting files (optional)
  - Scripts (optional)
  - Documentation (optional)
  - Assets (optional)

### Organization
- **Directories:** `scripts/`, `references/`, `assets/`

### Locations
1. **Workspace:** `.gemini/skills/` - Committed to version control, shared with teams
2. **User:** `~/.gemini/skills/` - Personal, available across workspaces

### CI/CD Integration
- Automated code quality assessment
- Documentation generation
- Deployment decision support
- Focus on specific development phases where AI provides measurable value

## 8. Gemini CLI - Extensions

### Overview
- **Purpose:** Package prompts, MCP servers, custom commands, themes, hooks, sub-agents, and skills
- **Format:** Pre-packaged, easily installable integrations
- **Connections:** Databases, design platforms, payment services, etc.

### Components
Extensions can include:
- Prompts
- MCP servers
- Custom commands
- Themes
- Hooks
- Sub-agents
- Agent skills

### Hook Integration
- Extension authors can bundle hooks directly within extensions
- Users install with single command, no manual configuration
- Extensions include `hooks/hooks.json` file
- JSON structure matches existing hooks configuration in `settings.json`

### Configuration Hierarchy
Gemini CLI merges configurations in this order (highest to lowest precedence):
1. Project settings (`.gemini/settings.json`)
2. User settings (`~/.gemini/settings.json`)
3. Hooks defined by installed extensions

## 9. Gemini CLI - MCP Server Integration

### Overview
- **Purpose:** Drastically improve Gemini CLI experience
- **Integration:** Seamless integration with FastMCP (Python's leading MCP library)
- **Tools:** Available to Gemini model like built-in tools

### Key Features

**Tools:**
- Allow Gemini CLI to perform actions, computations
- Interact with external APIs and databases
- Become active participant in workflows

**Prompts:**
- Use FastMCP-defined prompts as slash commands (e.g., `/promptname`)
- Streamlines interactions
- Makes commonly used prompts feel native to terminal

### Management Commands

Convenient commands to manage server configurations programmatically:
- Add MCP servers
- List MCP servers
- Remove MCP servers
- No need to directly edit JSON files

### Configuration
- **Location:** `mcpServers` configuration in `settings.json`
- **Purpose:** Locate and connect to MCP servers

### SDK Integration
- API automatically calls MCP tools when needed
- Connects to both local and remote MCP servers
- Instantiate FastMCP client
- Enter connection context
- Pass client session to Gemini SDK

### Getting Started
```bash
# Install Gemini CLI
npm install -g @google/gemini-cli@latest

# Install FastMCP (v2.12.3 or later)
pip install fastmcp>=2.12.3

# Create your server.py with custom tools and prompts
```
